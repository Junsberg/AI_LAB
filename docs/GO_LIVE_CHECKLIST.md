# 실매매 전환 체크리스트 (GO-LIVE)

원칙: **매매를 못 해서 잃는 건 허용, 설계·버그·로직 순서로 잃는 건 불허.**
아래 전 항목이 체크되고 `strategy/go_live.yaml`에 서명(날짜·해시)되기 전에는
`MODE=live`가 코드 레벨에서 거부된다.

## A. 페이퍼 실적
- [ ] 페이퍼 기간 ≥ 4주
- [ ] 청산 포지션 ≥ 100
- [ ] 기대값(평균 PnL/포지션) > 0, 표준오차 1배 이상 양수
- [ ] 최대 낙폭 ≤ `risk.max_daily_loss_sol` × 3
- [ ] 시그널별 어트리뷰션에서 최소 1개 시그널이 단독으로 양의 기대값

## B. 코드 전수 검토
- [ ] `execution/` 전 파일 라인 단위 리뷰 (2인분: 리뷰 스킬 high + 별도 세션 재검토)
- [ ] 서명·전송·잔고 조회 경로 2회 독립 검토
- [ ] 청산 엔진 우선순위(hard_stop → 배포자/KOL 매도 → 홀더 급감 → 볼륨 사망 → 원금 회수 → 트레일링) 테스트로 고정
- [ ] 리스크 캡이 **코드에서** 강제됨을 테스트 (params 값이 아니라 실행기가 거부하는지)

## C. 실패 시나리오 (각각 테스트 코드 존재)
- [ ] RPC 끊김/타임아웃 중 진입 → 중복 주문 없음
- [ ] 트랜잭션 실패(슬리피지 초과, 블록해시 만료) → 재시도 상한, 포지션 미생성
- [ ] 부분 체결 → 잔량 정확히 추적
- [ ] 봇 재시작 → DB 기준으로 포지션 복구, 유령 포지션 없음
- [ ] 가격 급변(±50% 1분) → 청산 엔진이 규칙대로 동작, 재량 없음
- [ ] 동일 토큰 중복 진입 차단
- [ ] 잔고 부족 → 진입 스킵, 에러 아님

## D. 이중 안전장치
- [ ] 봇 지갑 잔고 = 운용 자본 상한 (코드 버그와 무관하게 잃을 수 있는 최대치)
- [ ] 지갑 키는 로컬 `.env`만, 레포·클라우드·채팅 어디에도 없음 (grep으로 확인)
- [ ] 킬스위치: `KILL` 파일 생성 또는 `hypotheses` 테이블 플래그 → 신규 진입 중단 + 전량 청산
- [ ] 일일 손실 캡 도달 시 당일 자동 정지 (재시작해도 유지)

## E. 드라이런
- [ ] 실지갑 + 실서명 + **브로드캐스트 직전 중단** 모드 3일 무사고
- [ ] 드라이런 로그의 예상 체결가 vs 실제 시장가 괴리 측정 → 슬리피지 파라미터 보정

## F. 단계적 확대
- [ ] 1주차: 포지션당 최소 사이즈(0.05 SOL), 동시 3개
- [ ] 이상 없을 때만 2주차부터 params 값으로 확대
- [ ] 확대 시점마다 리뷰 노트에 기록
